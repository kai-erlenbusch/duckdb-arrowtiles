feat: DuckDB Native UDF and Structural Stability Hardening

This commit implements Phase 2 structural stability fixes and the Phase 3 Native UDF architecture:

1. Structural Stability (Phase 2 fixes):
   - Zero-Row Safeguard: `arrow_result.get_schema()` is now used to pre-initialize the Arrow `FileWriter`, ensuring empty result sets safely produce empty `.feather` files.
   - Graceful Error Bubbling: Extracted worker logic to `execute_export()` with standard `Result<usize, String>` bubbling. Panicking `.unwrap()`s were removed, allowing errors to seamlessly traverse the `mpsc` channel and surface natively in the DuckDB CLI.
   - Backpressure: Migrated from an unbounded channel to `mpsc::sync_channel(1)` to structurally prevent OOM exhaustion.

2. DuckDB Native UDF Pivot (Phase 3):
   - Pivot from sequentially sorting spatial data inside the Rust worker to utilizing DuckDB's multi-threaded C++ engine for spatial binning and sorting.
   - Registered `hilbert_xy` scalar function as a `VArrowScalar`.
   - The UDF automatically processes `Float64` vectors (lon, lat) into `UInt64` IDs via parallel Arrow evaluation.
   - The background worker is now a fully-sequential "dumb pipe" dedicated solely to IPC packaging.

3. Testing and Dependencies:
   - Added `vscalar` and `vscalar-arrow` features to duckdb-rs.
   - Included `fast_hilbert` in `Cargo.toml`.
   - Updated `test_load.py` to run full end-to-end UDF query simulation.
   - Updated README architecture diagram to reflect the new processing flow.
